# 건강기능식품 위원회 RAG V2 운영 안내

## 배포 순서

1. Supabase SQL Editor에서 `prisma/committee_rag_v2.sql`을 한 번 실행한다.
2. 애플리케이션을 배포한다.
3. 관리자 화면의 `RAG 청킹`에서 `V2 전체 재구축`을 실행한다.
4. `임베딩 실패`가 남으면 오류 내용을 확인한 뒤 `임베딩 누락 재처리`를 한 번 실행한다.

SQL을 먼저 적용하지 않으면 새 Prisma 필드를 사용하는 청크 API가 실패하므로 반드시 위 순서를 지킨다.

## V2 기본 설정

- 청크 목표 크기: 450자
- 청크 최대 크기: 600자
- 중첩: 약 75자
- 분할 우선순위: 문단 → 줄 → 문장 → 최대 길이
- 임베딩 모델: `gemini-embedding-001`
- 임베딩 차원: 768
- 문서 task type: `RETRIEVAL_DOCUMENT`
- 질문 task type: `RETRIEVAL_QUERY`
- 한 번의 Gemini 요청에 최대 16개 청크 포함

## API 호출 절감 규칙

- 콘텐츠 SHA-256 해시가 같으면 기존 임베딩을 재사용한다.
- 게시물 동기화 단계에서는 안건 임베딩을 만들지 않는다.
- 본문/PDF 재수집 단계에서는 회의 전체 임베딩을 만들지 않는다.
- 회차, 원료, 최신 회의, 위원 명단처럼 DB에서 직접 확정되는 질문은 질문 임베딩을 생략한다.
- 동일한 정규화 질문의 임베딩은 따뜻한 서버 인스턴스에서 30분간 재사용한다.
- 근거가 없는 심의 질문은 생성 LLM을 호출하지 않고 검색 실패 안내를 반환한다.
- pgvector가 준비되면 DB에서 상위 40개 후보만 조회한다.

## 이전 벡터와의 호환성

기존 기본 3,072차원 Gemini 벡터와 V2 768차원 벡터는 섞어 비교하지 않는다. V2 검색은 정확히 768차원인 벡터만 사용한다. 기존 JSON 컬럼은 롤백을 위해 당분간 유지하며 `embeddingVector` 컬럼은 DB 트리거가 자동으로 동기화한다.
